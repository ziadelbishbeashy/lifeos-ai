# LifeOS Document Brain — Step 7: Search Inside the Document

Step 7 adds direct passage search to the Document Brain workspace.

## User flow

Open a PDF -> Search tab -> enter a word, exact phrase, or concept -> LifeOS returns the original matching passages.

This is different from Ask Document:

- Search shows retrieved PDF passages.
- Ask Document generates a grounded answer from verified sources.

## Retrieval behavior

The search service combines:

1. Exact phrase scanning across all current document chunks.
2. Existing BM25 keyword retrieval.
3. Existing semantic embedding retrieval.
4. Existing hybrid ranking for broader concept matches.

Exact phrase matches are kept ahead of broader matches. Exact matches that also appear in hybrid retrieval retain hybrid relevance order.

If semantic retrieval is temporarily unavailable but an exact phrase exists, direct search still returns the exact passage. If the hybrid service already falls back to BM25, the UI explains that semantic search is unavailable and shows the available keyword results.

## Result data

Each result contains:

- rank
- page or page range
- section
- focused passage copied from the trusted chunk
- exact phrase indicator
- retrieval method
- display-only match strength
- keyword rank
- semantic rank
- semantic similarity when available
- matched query terms
- chunk identity

No AI answer is generated by this workflow.

## UI

The Document Brain tabs now include:

Overview | Insights | Search | Actions | Ask document

The Search tab works even when the PDF has not been analyzed, as long as readable text/chunks exist.

## New backend route

GET /documents/<document_id>/search?q=<query>

The route is protected by login and the retrieval services repeat project ownership checks.
